## What the verdicts mean

| Verdict | Meaning |
| --- | --- |
| <span class="tc-verdict tc-verdict-invalid">Invalid</span> | Writes a value the system does not accept, or calls something that no longer exists. Does nothing, silently. |
| <span class="tc-verdict tc-verdict-placebo">Placebo</span> | A real setting with no measurable effect. |
| <span class="tc-verdict tc-verdict-harmful">Harmful</span> | Measurably makes something worse. |
| <span class="tc-verdict tc-verdict-situational">Situational</span> | Can help on specific hardware, but not as a blanket recommendation. |
| <span class="tc-verdict tc-verdict-situational">Unproven</span> | Real, read by the system, and it does change behaviour. What is missing is evidence that any particular value is an improvement. |
| <span class="tc-verdict tc-verdict-invalid">Superseded</span> | Not wrong, but a documented setting does the same job and reverts cleanly. |

## Why the list is this long

Almost every entry here is one of three things.

**Correct advice for an older Windows.** The setting was real on Windows 7 or
Windows 10, the guide was accurate when it was written, and nobody went back to
re-check it against a current build. TCP Chimney Offload and `IoPageLockLimit` are
the clearest cases: both were genuine, both are gone.

**A real setting with an unproven benefit.** The value exists, the system reads it,
and it does change behaviour — but no measurement shows the change is an
improvement. `Win32PrioritySeparation` is the canonical example. These are marked
**Unproven** rather than Placebo, because "nothing measurable has been shown" and
"nothing happens" are different claims, and only the first one is defensible.

**A value copied wrong, then copied again from the copy.** `TcpAckFrequency = 0`
is not in the key's valid range. `*EEE = 1` enables the feature that the comment
above it claims to disable. Both appear in hundreds of scripts.

The failure mode that keeps all three alive is that Windows does not complain.
`Set-ItemProperty` writes any name you give it, the value appears in `regedit`, and
nothing reads it. Checking a value against
[the binary that would read it](../../guides/reading-the-binary/) takes about thirty
seconds and rules out an entire category of these.

The defence against the other two is the same in both cases: know the mechanism,
check the Windows version, measure the result. That is what
[how a tweak earns its place](../../start/method/) is for.
