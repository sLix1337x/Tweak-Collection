Every service in Microsoft's own configuration table, with its default startup
type, Microsoft's recommendation, and what stops working if you disable it.

:::caution[This table is Microsoft's IoT guidance, not desktop guidance]
The recommendations come from [Guidance on configuring system
services](https://learn.microsoft.com/en-us/windows/iot/iot-enterprise/optimize/services),
whose **Applies to** line lists Windows 11 IoT Enterprise, Windows 10 IoT
Enterprise and IoT Enterprise LTSC 2021 — and no general-client SKU. It is written
for a device maker "building a fixed-function, specialized device".

Microsoft publishes no equivalent table for desktop Windows 11. Every service list
that tells you "Microsoft says this is OK to disable" is quoting this page, whether
or not it knows.
:::

This matters because a fixed-function device has no user, no printer, no Store apps
and often no updates. On that device, disabling Windows Update and the audio
endpoint builder is reasonable. On yours it is not — and both are marked
`OK to disable` below. The **Desktop caveat** filter shows the eleven rows where the
two situations come apart.

## What the recommendations mean

Microsoft's own definitions, condensed:

| Value | Microsoft's meaning |
| --- | --- |
| **OK to disable** | Useful to some enterprises but not all; a security-focused enterprise that does not use it can disable it. |
| **Don't disable** | Disabling it prevents specific roles and features from working correctly. |
| **No guidance** | The effect "isn't fully evaluated" — so the default should not be changed. Not a synonym for safe. |
| **Already disabled** | Off by default; no policy needed. |
| **Should be disabled** | Should never be enabled on a well-managed enterprise system. |

`No guidance` is the value most often misread. It means unexamined, not harmless.

## Three rows to distrust

The table is transcribed faithfully, which means it inherits the source's problems:

- **`AJRouter`** — AllJoyn was [deprecated in August
  2023](https://learn.microsoft.com/en-us/windows/whats-new/deprecated-features)
  and the service is absent from current Windows 11 builds. Nothing to disable.
- **`DiagTrack`** — marked `OK to disable` here, but Microsoft's Server guidance
  marks the same service `No guidance`, and for client Windows the documented way
  to reduce telemetry is the **Allow diagnostic data** policy, not the service.
  This collection disables both, deliberately and for a stated reason, on the
  [privacy page](../../tweaks/privacy/#privacy.services-telemetry).
- **Per-user services** (shown as `_*`) — these exist once per signed-in session
  with a random suffix, so `AarSvc` in the table is really `AarSvc_9f024` on your
  machine. The startup type is set on the template service in the registry; the
  per-session instance cannot be configured in Services.msc.

## Before you disable anything here

1. **Manual before Disabled.** A Manual service that nothing asks for never starts,
   and the failure mode is recoverable.
2. **One at a time, with a reboot.** Twenty at once means twenty suspects when
   something breaks next week.
3. **Expect no frame-rate change.** An idle service costs a few megabytes of
   paged-out working set and no CPU. That is the whole reason
   [this collection disables three of them](../../tweaks/services/) and stops.

Microsoft's Server guidance is blunter than anything on the IoT page, and it
applies here too: they do not recommend policies that disable services which are
not disabled by default.
